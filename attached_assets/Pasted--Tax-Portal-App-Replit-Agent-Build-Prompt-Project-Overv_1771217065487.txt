# Tax Portal App - Replit Agent Build Prompt

## Project Overview
Build a mobile-first Tax Portal web application with separate client and admin interfaces. The app should enable clients to upload tax documents, sign returns digitally, chat with tax professionals, and view completed tax returns. The admin side should allow tax professionals to manage clients, upload completed returns, and respond to client inquiries.

---

## Technical Stack
- **Frontend:** React.js with TypeScript
- **Backend:** Node.js with Express
- **Database:** SQLite (for local development) or PostgreSQL (production-ready)
- **Authentication:** JWT with local storage (client-side credential storage)
- **File Storage:** Local file system or cloud storage integration ready
- **Email Service:** NodeMailer for password reset emails
- **Styling:** Tailwind CSS for mobile-first responsive design
- **Icons:** React Icons or Lucide React

---

## Core Features & Requirements

### 1. AUTHENTICATION SYSTEM
**Login Flow:**
- Email and password login form
- "Forgot Password" link that triggers email reset flow
- Password reset email with secure token (expires in 1 hour)
- Reset password page where users create new password
- Successful login stores JWT token locally (localStorage)
- Auto-login if valid token exists
- Logout clears local credentials

**Security:**
- Passwords hashed with bcrypt (min 8 characters)
- JWT tokens with 7-day expiration
- Secure password reset tokens
- Client-side credential storage only
- Input validation and sanitization

**User Roles:**
- Client (default)
- Admin/Tax Professional

### 7. DATABASE SCHEMA

#### Users Table
```sql
- id (primary key)
- email (unique)
- password_hash
- full_name
- phone
- address
- role (client/admin)
- created_at
- last_login
- is_active
```

#### Documents Table
```sql
- id (primary key)
- user_id (foreign key)
- file_name
- file_path
- file_size
- file_type
- category
- upload_date
- status (draft/submitted/reviewed)
- admin_notes
```

#### Signatures Table
```sql
- id (primary key)
- user_id (foreign key)
- signature_data (base64)
- signed_at
- return_id (foreign key)
- ip_address
```

#### Tax Returns Table
```sql
- id (primary key)
- user_id (foreign key)
- file_name
- file_path
- upload_date (by admin)
- status (pending_signature/signed/complete)
- admin_notes
- tax_year
```

#### Messages Table
```sql
- id (primary key)
- sender_id (foreign key to users)
- recipient_id (foreign key to users)
- message_text
- attachments (JSON array)
- sent_at
- read_at
- is_read
```

#### Crypto Transactions Table
```sql
- id (primary key)
- user_id (foreign key)
- date
- crypto_type
- transaction_type
- amount
- usd_value
- cost_basis
- notes
- created_at
- cointracker_sync (boolean)
```

#### Password Reset Tokens Table
```sql
- id (primary key)
- user_id (foreign key)
- token (unique)
- created_at
- expires_at
- used (boolean)
```

### 8. API ENDPOINTS

#### Authentication
- `POST /api/auth/register` - Create new user account
- `POST /api/auth/login` - Login user
- `POST /api/auth/forgot-password` - Request password reset
- `POST /api/auth/reset-password` - Reset password with token
- `POST /api/auth/verify-token` - Verify JWT token
- `POST /api/auth/logout` - Logout user

#### Documents
- `GET /api/documents` - Get user documents
- `POST /api/documents/upload` - Upload document
- `DELETE /api/documents/:id` - Delete document
- `GET /api/documents/:id/download` - Download document
- `PATCH /api/documents/:id/status` - Update document status (admin)

#### Signatures
- `POST /api/signatures` - Save signature
- `GET /api/signatures/:userId` - Get user signatures
- `POST /api/signatures/sign-return` - Sign tax return

#### Tax Returns
- `GET /api/returns` - Get user returns
- `POST /api/returns/upload` - Upload return (admin)
- `GET /api/returns/:id` - Get specific return
- `PATCH /api/returns/:id/notify` - Notify client of new return

#### Messages
- `GET /api/messages/:userId` - Get conversation
- `POST /api/messages` - Send message
- `PATCH /api/messages/:id/read` - Mark as read
- `GET /api/messages/unread-count` - Get unread count

#### Crypto
- `GET /api/crypto/transactions` - Get crypto transactions
- `POST /api/crypto/transactions` - Add crypto transaction
- `PUT /api/crypto/transactions/:id` - Update transaction
- `DELETE /api/crypto/transactions/:id` - Delete transaction
- `GET /api/crypto/summary` - Get crypto tax summary

#### Admin
- `GET /api/admin/clients` - Get all clients
- `GET /api/admin/dashboard-stats` - Get dashboard statistics
- `POST /api/admin/clients/invite` - Invite new client
- `GET /api/admin/documents/all` - Get all client documents
- `GET /api/admin/messages/all` - Get all conversations

### 9. SECURITY CONSIDERATIONS

1. **Input Validation:** Validate all user inputs on both client and server
2. **File Upload Security:** 
   - Limit file sizes (max 10MB per file)
   - Whitelist allowed file types
   - Scan for malware
   - Sanitize file names
3. **SQL Injection Prevention:** Use parameterized queries
4. **XSS Protection:** Sanitize all user-generated content
5. **CSRF Protection:** Implement CSRF tokens for forms
6. **Rate Limiting:** Limit API requests to prevent abuse
7. **HTTPS Only:** Force SSL in production
8. **Session Management:** Secure JWT implementation
9. **Data Encryption:** Encrypt sensitive data at rest
10. **Audit Logging:** Log all admin actions
